# Dclip

(Formerly Clipbot. The code, bundle id `io.linus.clipbot` and storage keep that name, so data and
permissions carry over.)

A private clipboard history and snippets app for macOS. It has Maccy's search popup but is
built to be safe: passwords are never recorded, everything on disk is encrypted, and the
app has no network access at all.

## Using it

| Shortcut | Opens |
|---|---|
| **⇧⌘V** | History and snippets |
| **⌃⌘V** | History only |
| **⇧⌘B** | Snippets only |

The popup opens at the mouse cursor with the search box focused. Type to filter: every word must
appear somewhere in the clip's text (up to its first 2,000 characters), in any order, ignoring case
and accents. Then:

| Key | Does |
|---|---|
| **↑ ↓** (or **⌃P ⌃N**), **⌘↑ ⌘↓** | Move the selection, jump to the first or last |
| **Return** or click | Paste the selected item into the app you were in |
| **⌘1**…**⌘9**, **⌘0** | Paste row 1–10 |
| **⌥⌫** | Delete the selected clip from history |
| **Esc** | Clear the search, then close |
| **⌥⌘⌫**, **⌘,**, **⌘Q** | Clear History…, Settings…, Quit |

Pressing the shortcut again closes it. The footer also has **Edit Snippets…**. Clicking the
clipboard icon in the menu bar opens the popup under it. You
can hide the icon in Settings, then reach Settings by opening Dclip again from Spotlight.

## Install

```bash
scripts/install.sh
```

This builds the Release version, installs it to `/Applications/Dclip.app` and starts it.
On first launch it adds itself to Login Items. Grant two permissions:

- **Accessibility**, so it can paste for you (System Settings → Privacy & Security → Accessibility).
- **Clipboard access**, if macOS asks.

## Security model

- **Passwords from password managers are never recorded.** A copy is dropped, before its
  contents are read, in any of these cases:
  - it carries a password-manager marker (`org.nspasteboard.ConcealedType`/`TransientType`/`AutoGeneratedType`, 1Password's legacy type);
  - it comes from an app on the ignore list (1Password, Apple Passwords, Keychain Access, editable in Settings);
  - a password field has focus (secure input is on).
- **Copies containing an API key are kept for 10 minutes, in memory only.** Text with a
  well-known secret format anywhere in it, such as a line from an `.env` file or a message that
  happens to include a key, still shows in history, so nothing you copy is lost by accident. It
  is never written to disk, not even encrypted. It disappears 10 minutes after you last copied it,
  on Clear History, or when Dclip quits. Covered formats: OpenAI/Anthropic `sk-…`, GitHub tokens,
  AWS key IDs, Slack and Stripe live keys, and PEM/PGP private keys. This applies to every text
  form of a copy, including text that comes with an image or PDF.

  **Limit:** a secret with no password-manager marker and no recognisable format is recorded
  like any other text. For example, a password piped to `pbcopy` from a terminal or typed out
  by hand.
- **Encrypted at rest.** Every clip, the history index, thumbnails and snippets are sealed
  with AES-256-GCM. The keys are bound to this Mac's **Secure Enclave**: the Keychain holds
  only a Secure Enclave key blob, so the data can't be decrypted on any other machine,
  even after a Keychain migration. The storage is in the app's sandbox container (mode 0700,
  excluded from Time Machine), which macOS also protects from other apps.
- **Clear History** deletes every clip and replaces the key, so leftover bytes on disk can't
  be read with the current key. (An old Keychain backup *on this same Mac*, together with old
  disk snapshots, could in principle still open them.)
- **Hostile copies can't freeze or crash it.** All clipboard data is read in a separate,
  sandboxed helper process (`ClipReader.xpc`). That includes macOS's own RTF/PDF/image
  converters, which run in whichever process asks for a converted format. The stress suite found
  a 170-byte RTF that sends Apple's RTF parser into an infinite loop
  (`Tests/Fixtures/rtf-tokenizer-hang.rtf`). With the helper, that copy is dropped: the helper's
  watchdog ends it after 2 s, launchd starts a fresh one, and Dclip never stops responding.
- **No network.** The App Sandbox has no network entitlement, so the OS blocks every
  connection. There's no analytics, crash reporting, update checks or third-party libraries. The popup's
  UI is adapted from [Maccy](https://github.com/p0deje/Maccy) (MIT, `docs/licenses/Maccy.txt`).
- **Nothing syncs.** Dclip's own pastes are marked current-host-only, so Universal
  Clipboard never sends them to your other devices.
- **Locked-down binary.** It runs with Hardened Runtime and no exceptions, and has no debugger
  entitlement in Release. It exposes no URL schemes, AppleScript, Services or extensions.
  `scripts/check-security.sh` verifies all of this on a build.
- **Logs never contain clip content.** Only event names and reasons are logged, such as
  "clip dropped: marker".

- **Can't be quietly swapped.** Install with `scripts/install.sh --lock` so the app is
  root-owned and nothing running as you can replace it. If macOS ever asks you again to
  allow Dclip in Accessibility or the Keychain when you haven't reinstalled it, say no and
  investigate: a replaced app loses those permissions and has to ask.
- **Debug builds are isolated.** They use the bundle id `io.linus.clipbot.debug`, with their
  own container and Keychain items, so a debuggable build can never open the real data.

Outside Dclip's control: keep **FileVault** on. Also consider turning off Handoff if you
don't want *other* apps' copies syncing via Universal Clipboard.

### Snippets backup

Snippets are encrypted with a key that only exists on this Mac. To keep a backup or move
them to a new Mac, use **Edit Snippets → Export Snippets…**, which writes a plain,
unencrypted XML file in Clipy's format. It's readable only by you and saved to Downloads by
default, which iCloud doesn't sync. Import it with **Import from Clipy XML…**. If the key
is ever lost, Dclip moves the unreadable files into an `Unreadable-<date>` folder and
sets the old Keychain entry aside, renamed `….unreadable-<date>`. It never deletes either, and
then starts fresh.

## Development

```bash
scripts/test.sh                    # unit tests (ClipbotCore)
scripts/test.sh HistoryStoreTests  # one test class
scripts/check-security.sh          # lockdown checks on the Release build
```

- `project.yml` is the xcodegen spec; the `.xcodeproj` is generated and not committed.
- `Sources/ClipbotCore` holds all the logic (filter, crypto, stores, capture), with unit tests.
- `Sources/Clipbot` is the thin AppKit/SwiftUI app.
- Builds are signed with the personal Apple Development certificate (team `8L83KP4DT8`), so
  permissions survive rebuilds.
- Design: `docs/superpowers/specs/2026-11-07-clipbot-design.md`.

Diagnostics:

```bash
/usr/bin/log stream --predicate 'subsystem == "io.linus.clipbot"' --info
```
